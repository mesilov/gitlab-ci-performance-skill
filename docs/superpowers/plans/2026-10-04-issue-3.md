## Shared runtime interface

Timing evidence is a JSON object with `id`, fixed-code `label`, `category`,
`duration_seconds`, `start_seconds`, `end_seconds` (nullable positions relative to
job start), `first_line`, `last_line`, `timing_source`, `position_source`, `cached`,
`complete`, and `substeps` (same shape, empty for leaves). Sources are
`runner_section`, `buildkit_reported`, `logged_interval`; positions are
`section_markers`, `log_timestamps`, `unknown`. IDs are stable within attempt.

`trace_parser.parse_trace(raw: bytes, job: dict, analyzed_at: str,
truncated: bool = False)` returns `job_id`, `trace_status`, `trace_sha256`,
`trace_bytes`, `processed_bytes`, `trace_lines`, `timestamp_lines`, `analyzed_at`,
`parser_version` (2.0.0), `phases`, `builds`, `commands`, `limitations` (fixed
codes). Each build has `id`, `label` (`image_build`), `start_seconds`,
`end_seconds`, `span_seconds`, `push_coverage` (`unknown`, `outside`, `recorded`),
`operations`. No arbitrary raw strings or private names enter trace evidence.

V2 report contains existing project/timezone/input provenance plus `types`
(stable id/name/stage/purpose/source_count/retained_ids/latest_attempt_id/
status_counts/comparison/windows), bounded safe `jobs`/`pipelines`, `details`
(parser summaries keyed by job_id), `default_type_id`, `attention_type_id`,
`same_ref_views` (existing v1 comparisons), and `coverage`.

Comparison contains `scope`, `sample_ids`, `known`, `missing`, `latest_seconds`,
`baseline_seconds`, `delta_seconds`, `delta_percent`, `eligible_increase`.
Windows have `size` (32/64), `offset` (0/32), `count`, `attempt_ids` (newest first),
`from`, `to`, `unit` (`seconds`/`minutes`), `successful_n`, `execution`/`queue`/
`total` metrics (existing metric shape), `queue_spike`, `priorities`.
Priority has `category`, `median_cost_seconds`, `known`, `missing`, `partial`,
`guidance_url`, `direction` (fixed code), `evidence` (job_id/build_id/operation_id/
phase_id/command_id and representative `duration_seconds`, nullable unused IDs).
Category median and evidence duration are always separate fields.

Labels/categories are fixed English machine codes, translated by the renderer.
Job names, refs, SHA, IDs and catalog prose remain source data and are escaped.
The UI formats and selects precomputed values; it never recalculates medians,
unions, priorities or baseline eligibility.
